# Reproducing the paper

```bash
python3 scripts/reproduce_paper.py            # everything, about 15 minutes on one workstation
python3 scripts/reproduce_paper.py fig1 fig4  # selected families
python3 scripts/reproduce_paper.py --list     # the family and module names
python3 scripts/reproduce_paper.py --out recomputed.tsv   # also write every comparison, with q
```

It needs numpy only, reads nothing outside the repository, prints one line per family and per value module,
then a summary, and exits 0 when everything agrees with the paper. `E2G_PROCS` and `E2G_WORKERS` set the number
of worker processes the slower modules use. Against the paper, all 419 comparisons of Supplementary Table 2
(difference, 95% interval and p), every q-value and verdict, and all 6,456 printed values agree.

## The four failure modes, and where to see each

The paper's claim is that protocol choices move results as much as model choice
does. Each failure mode is visible in the shipped configs and scores.

| failure mode | where to look |
|---|---|
| **Reachability conflation** | Fig. 1, Fig. 2 and the by-support supplementary figures: the same scores ranked on all pairs, on the pairs every model can reach (`common-reachable`) and on each model's own receptive field (`rf-*`). `scripts/evaluate.py` prints every support side by side |
| **Model–protocol entanglement** | the three reproduction config families (`configs/avsec2021-*`, `linder2025-*`, `avsec2026-*`), each mimicking one paper's own protocol, against the matched `configs/unified-t1-*` protocol that holds every parameter fixed across the three trunks; and the anchor and readout arms of Fig. 3 |
| **Cross-gene scale miscalibration** | Fig. 4: gene-readout normalisation (`log_scalar`) and gradient-map normalisation (`normalise`), e.g. `unified-t1-N4-*` and `unified-t1-S2n-*` against the matched arms |
| **Cell-type mismatch** | Fig. 5: `cell_type` `k562` (the benchmark's own cell type) against `all` (every CAGE sample the trunk predicts) and the random non-K562 draws `rand2-s*` / `rand1-s*` |

## How a config maps to a result

`reproducing.tsv` is the ledger: one row per score table in `scores/`, giving the
config, the command-line overrides, the anchor cache (if any), the figures that
use the table, and a note.

```
result                                                               config                                     overrides
scores/unified-t1/unified-t1-A1w-enformer-single-tss.scores.tsv.gz   configs/unified-t1-backbone-enformer.yaml  anchor=single-tss
scores/unified-t1/unified-t1-N1-enformer-single-tss-agnostic.scores.tsv.gz  configs/unified-t1-backbone-enformer.yaml  anchor=single-tss cell_type=all
```

So the cell-type experiment of Fig. 5 is a **one-token override on an unchanged
config**, `--set cell_type=all`, never a code change:

```bash
python3 score_eg.py --config configs/unified-t1-backbone-enformer.yaml \
    --set anchor=single-tss --set cell_type=all --fasta /path/to/hg38.fa \
    --out scores.tsv --manifest manifest.json
```

Every row's config plus overrides resolves, on this engine, to exactly the
protocol the run recorded when it produced the shipped table (checked for each
of the 103 runs Supplementary Table 3 lists). Two Borzoi tables have their own config file
(`unified-t1-S2n-*`, `unified-t1-S3n-*`).

Two kinds of rows are not single runs of `score_eg.py`:

- `(derived)` rows are ISM tables at another `ism_statistic`, reduced from the
  run's stored per-shuffle draws by `scripts/ism_statistic_tables.py` (the note names
  the run and the command). An ISM run reduces its draws to one statistic;
  `--ism-draws` keeps them, so every other statistic, the strand slice
  (`--strand-mask auto`) and the K-draw prefixes are post-processing, not
  another pass over the model. The paper's matched ISM protocol reads
  `log_abs_diff`, the mean over shuffles of |log2 u_wt - log2 u_mut|.
- `(baseline)` rows are ABC, ABC*, their denominator-free variants and
  distance, regenerated by `scripts/baselines/score_baselines.py` (see
  [baselines.md](baselines.md)).

Every table from a run ships its manifest beside it (`<table>.manifest.json`):
the config and overrides, the 42 parameters they resolve to, the table's pair
counts and, where the run recorded them, path-free facts about the backend. The `anchors` column names a precomputed
MAJOR-TSS cache in `data/` (pass it with `--anchors`; without it the engine
recomputes the anchors, one forward pass per candidate TSS), and `figures`
names the paper figures that read the table.

## How the statistics are computed

`scripts/reproduce_paper.py` runs one module per family of comparisons
(`scripts/paper/fam_*.py`; a family is one figure, as in Supplementary Table 2),
one per reproduction of published results (`rep_*.py`) and one per remaining
supplementary item (`sup_*.py`). The modules need numpy only, read nothing
outside the repository (`scripts/paper/harness.py`), and implement the paper's
statistics:

- pooled auPRC is tie-aware step-wise average precision: one threshold per
  distinct score, so tied scores, such as the zeros of pairs a model cannot
  reach, enter the ranking together;
- within-gene auROC uses mid-ranks for ties and averages over the genes with at
  least one positive and one negative pair;
- intervals and p-values come from 10,000 paired bootstrap replicates over the
  663 connected components of the gene–enhancer graph (seed 20260816), every
  compared arm scored on the same replicate; p = min(1, 2 min(P(Δ ≤ 0),
  P(Δ ≥ 0)));
- Benjamini–Hochberg runs within each family; a p below the bootstrap
  resolution enters at 2 × 10⁻⁴ and its q is an upper bound.

Each figure's own conventions are kept: for example Fig. 1A's brackets are
differences of its bars as printed (four decimals), and Fig. 4 reads every arm
at σ = 300 with the other normalisation applied through each gene's
normaliser. A module recomputes a replicate's average precision from counts per
distinct score rather than re-sorting rows; it is identical to scoring the
concatenated resample, which keeps 10,000 replicates fast in plain numpy.

`paper/expected/` holds what the paper prints: `supp_table2.tsv` (the 419
comparisons of Supplementary Table 2) and `values.json` (the values each figure
and passage prints, keyed by the label each module's `values()` returns).
`paper/data/` holds the derived inputs:

| file | what it is |
|---|---|
| `ism_matched_perdraw.npz` | per pair and per perturbation draw, the ISM statistics the ISM figures read, after the strand slice: the mean of the first K draws is exactly the K-draw statistic |
| `linder2025_ism_signed_per_pair.tsv.gz` | the signed statistic of Linder et al. (2025)'s released code (`signed_mean`: the mean of the signed draws, which are log fold changes under `log_scalar: true`), per pair, for the two ISM runs on the authors' tables; `scripts/ism_statistic_tables.py --statistics signed_mean` reproduces it from the runs' draws |
| `epcrispr_benchmark_K562.tsv.gz` | the K562 benchmark as released ([EngreitzLab/CRISPR_comparison](https://github.com/EngreitzLab/CRISPR_comparison) v1.0.0), for the screen each pair comes from (the screens supplementary figure) |
| `avsec2021_*.json`, `linder2025_fig4_values.json`, `avsec2026_targets.json` | the published values the three reproductions are compared with |
| `gencode_linder2025_*.json`, `avsec2021_crop_straddlers.*.tsv` | annotation and pair lists the reproductions' cohort cuts read |
| `baselines/` | see [baselines.md](baselines.md) |

## What is not reproduced

- Figure rendering is not included. The values each figure prints are recomputed
  by `scripts/reproduce_paper.py`; the figures themselves are in the paper.
- A few printed items are not functions of the scores and are not
  recomputed: the GPU-hours, run times and model-call ratios (from run logs),
  panel A of the ISM perturbation-mode figure (CpG and GC content of perturbed
  windows, which needs the genome), the estimated published whiskers drawn in
  the Avsec et al. (2021) reproduction, and constants such as receptive-field
  sizes.
- The ISM draws themselves are not shipped (tens of MB per run). Re-running an
  ISM config with `--ism-draws` regenerates them, and `scripts/ism_statistic_tables.py`
  reduces them to the shipped tables.
